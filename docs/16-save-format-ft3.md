# 16. FT3 세이브 포맷 전체 지도 (원작 에디터 분석 완료)

원작 DOS 에디터(`EDITER.EXE`) 메뉴 **120개 항목**을 전수 조사해 세이브 구조를 확정했습니다.
이 문서가 있으면 앞으로 이런 한국산 DOS 에디터/세이브는 같은 방식으로 바로 풀립니다.

---

## 1. 원작 에디터의 동작 모델 (한국산 DOS 에디터 공통 패턴)

```
게임 데이터 파일(DAT) ──┐
  CHAR.DAT   8명  (레코드 164B)      ├─► 에디터가 메뉴를 "데이터 기반"으로 생성
  CLASS.DAT  24직업(레코드 38B)      │     (항목 이름 = 캐릭터명/직업명, 항목 수 = 약 120)
  ITEM.DAT   아이템명+설명            │
  TECH/MAGIC/MNSTR …                 │
                                     ▼
세이브(.FOS, 21,704B) ◄── 에디터가 **고정 오프셋**으로 읽고/쓴다
```
- 코드에 큰 오프셋 상수(0x5480 등)가 **없습니다** → 오프셋은 **데이터 파일 레코드 크기로 계산**하기 때문.
  ⇒ 정적 문자열/상수 검색으로는 안 나오고, **값 변경 diff** 또는 **합성 세이브**가 가장 빠른 길입니다(4절).
- 컴파일러: **Turbo Pascal** (파일 런타임 형태 `[SI+0x1]`=핸들, `[SI+0x13]`=버퍼로 확인)
- 한글 UI: 자체 한글 TUI 라이브러리 (`blEDITER`, `blHINPUT`, `blHTGET` 모듈)

## 2. 세이브 파일 지도 (FT3, 21,704 bytes)

**캐릭터 순서**: `아크 → 아미 → 카인 → 쉬엔카 → 에린 → 레오 → 시엘라 → 디언` (i = 0..7)
(`DAT\CHAR.DAT`, 레코드 164바이트)

| 필드 | 오프셋 | 크기 | 비고 |
|---|---|---|---|
| **HP[i]** | `0x0014 + i*2` | u16 | |
| **HP-MAX[i]** | `0x0024 + i*2` | u16 | |
| **SP[i]** | `0x0034 + i*2` | u16 | |
| **SP-MAX[i]** | `0x0044 + i*2` | u16 | |
| **경험치[i]** | `0x0F20 + i*0x4C0` | u32 | i 증가마다 +0x4C0 (확인: 0F20→13E0→18A0→1D60→2220) |
| **직업 스탯[캐릭터][직업]** | `0x056E + i*0x4C0 + c*4` | u16×2 | 캐릭터 블록 간격 0x4C0, 직업 간 4바이트 |
| **소지금(돈)** | `0x5480` | u32 | A/B diff + 에디터 표시값 일치 |
| **코인** | `0x5484` | u32 | |

**직업 스탯 블록 (캐릭터별 시작 오프셋, 실측)**
```
아크   0x056E      아미 0x0A2E      카인 0x0EEE      쉬엔카 0x13AE
에린   0x186E      레오 0x1D2E      시엘라 0x21F6    디언 0x26AE
(각 블록 = 직업 24개 × 4바이트)
```
**파일 끝 부분**에도 별도 표가 있음: `0x5480` 소지금·코인 / `0x6160` 등.

## 3. 확정 검증 방법 (원작 에디터를 오라클로)

| 방법 | 내용 |
|---|---|
| **값 변경 diff** | 에디터에서 HP-MAX 를 7777 로 저장 → 파일에서 `0x0024` 두 바이트만 변경 확인 |
| **합성 세이브** ⭐ | 각 u16 오프셋 X 에 `X/2` 를 심은 세이브를 만들면, 에디터 화면의 **표시값이 곧 오프셋×2** (u32는 하위워드) |
| 메뉴 순회 | 에디터 메뉴를 120회 순회하며 패널을 캡처 → OCR(한+영) → (항목명, 값, 오프셋) 표 자동 생성 |

## 4. 정적분석 기록 (재현용)

```powershell
# 1) PKLITE 1.12 압축 해제 (pkla.py 로 버전 확인 → depklite 로 해제)
python pkla.py -p EDITER.EXE            # → "created by: PKLITE 1.12", cmpr data @784
./depklite -o editer.bin EDITER.EXE 784 # → 112,472 bytes
# 2) Ghidra headless (16비트 리얼모드) + INT 21h 지점 강제 디어셈블
analyzeHeadless <proj> e -import editer.bin -processor "x86:LE:16:Real Mode" \
  -loader BinaryLoader -loader-baseAddr 0x0 -postScript IntScan.java
```
- 식별된 파일 I/O 지점: open `0x78a6`(DX=0x15dd 파일명 버퍼), TP read `0xa986`/`0xa9a9`,
  write `0xa9b2`, close `0xa9c2`, open(런타임) `0x1000:03d6`
- 문자열이 폰트 데이터로 인코딩되어 있고, 필드 최대값(9999/99999999)은 자릿수 계산값 → 문자열/상수 검색 불가

## 5. 다른 게임에 적용하는 순서 (일반 절차)

1. 게임 폴더의 `DAT\*.DAT` 에서 **캐릭터/직업/아이템 이름**(CP949)과 **레코드 크기** 확인 → 세이브 배열 개수/순서 추정
2. 원작 에디터를 DOSBox(SVN-Daum)로 실행
3. **합성 세이브**(각 u16 = 오프셋/2) 투입 → 메뉴 순회 캡처 → 표시값으로 오프셋 역산
4. 애매한 항목은 **값 변경 후 diff** 로 확정 (체크섬/엔디안 동시 확인)
5. `editor/fos-editor.html` 에 표를 추가 (이 파일이 계속 확장되는 범용 에디터)
