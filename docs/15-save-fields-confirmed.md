# 15. 세이브 에디터 — 필드 오프셋 확정 (합성 세이브 기법)

`editor/fos-editor.html` 에 들어간, **검증된** 오프셋입니다.
방법: 원작 DOS 에디터(`EDITER.EXE`)를 DOSBox 로 실행하면서
**(1) 값을 바꿔 저장 → 파일 diff**, **(2) 각 오프셋에 고유값을 심은 합성 세이브를 물려 표시값 = 오프셋** 으로 확인.

---

## 1. 확정 필드 (FT3, 파일 크기 21,704 bytes)

| 항목 | 오프셋 | 크기 | 검증 방법 |
|---|---|---|---|
| **소지금(돈)** | `0x5480` | u32 LE | A/B 세이브 diff(200 vs 100) + 에디터 표시 43147 일치 |
| **코인** | `0x5484` | u32 LE | 합성 세이브(값 `0x2A432A42`) → 표시 709044802 |
| **HP[i]** | `0x0014 + i*2` | u16 | 에디터로 HP-MAX 변경 후 diff, 합성값 10=0x14/2 |
| **HP-MAX[i]** | `0x0024 + i*2` | u16 | 에디터에서 7777 저장 → `0x0024` 두 바이트만 변경 |
| **SP[i]** | `0x0034 + i*2` | u16 | 합성값 26=0x34/2, 연속 항목 +2 패턴 |
| **SP-MAX[i]** | `0x0044 + i*2` | u16 | 합성값 34=0x44/2 |
| **경험치(캐릭터0)** | `0x0f20` | u32 | 에디터 표시 222852 = 파일값 유일 위치, 합성값 일치 |

- **i = 0 … 7 (파티 8명)**. 스탯별로 **연속 u16 배열**입니다(캐릭터 레코드가 아님!).
  ```
  0x0014~0x0023 : HP[0..7]
  0x0024~0x0033 : HP-MAX[0..7]
  0x0034~0x0043 : SP[0..7]
  0x0044~0x0053 : SP-MAX[0..7]
  0x0054~       : 그 외 스탯 배열들(전사/마법/…)
  ```
- 원작 에디터 메뉴는 **약 100개**이며 `HP / HP-MAX / SP / SP-MAX / 경험치` + 직업별 스탯(전사·마법·마도·닌자·풍수·신관·현자·트랩·음유 …)들로 구성됩니다.
  나머지 스탯 배열도 같은 방식(합성 세이브)으로 언제든 확정 가능합니다.

## 2. 합성 세이브 기법 (핵심)

각 u16 오프셋 X 에 `X//2` 를 심어 둔 21,704 바이트 세이브를 만들고 에디터로 열면,
**화면에 표시되는 숫자가 곧 오프셋×2** 가 됩니다. (u32 필드는 하위 워드가 `X/2`)

```python
for off in range(0, 0x6000, 2):
    struct.pack_into("<H", d, off, off // 2)
```
→ 에디터에서 메뉴를 순회하며 패널을 캡처하면 필드 표가 자동으로 나옵니다.
(에디터가 파일을 1:1 로 버퍼에 올리고 오프셋으로 접근한다는 사실도 이걸로 증명됨)

## 3. 원작 에디터(EDITER.EXE) 정적분석 기록

| 항목 | 값 |
|---|---|
| 형식 | **PKLITE 1.12** 압축 DOS EXE (66,711 bytes) |
| 압축 데이터 위치 | `784` (`cmpr data @784`, large 모드) |
| 해제 도구 | **depklite**(hackerb9, CLI) → 112,472 bytes 이미지 |
| 언어 | **Turbo Pascal** (TP 파일 런타임 패턴: `[SI+0x1]`=핸들, `[SI+0x13]`=버퍼) |
| 한글 지원 | 자체 한글 TUI 라이브러리 (`blEDITER`, `blHINPUT`, `blHTGET` 모듈) |
| 디스어셈블 | Ghidra 12 headless (`x86:LE:16:Real Mode`, INT 21h 지점 강제 디스어셈블) |
| UI 문자열 | 폰트 데이터로 인코딩 → 문자열 검색으로는 안 나옴 |
| 필드 최대값 | `9999`/`99999999` 는 계산값(자릿수) → 상수 검색 불가 |
